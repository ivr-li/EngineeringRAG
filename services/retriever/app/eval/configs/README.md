## Параметры

### `index_version`

Логическая версия поискового индекса, используемая при расчёте метрик.

Если в датасете заполнены `resolved_chunk_ids`, значение определяет набор
эталонных ID чанков:

```json
"resolved_chunk_ids": {
  "index_v1": ["chunk-id-1"],
  "index_v2": ["chunk-id-8"]
}
```

Сейчас используется значение `current`, а `resolved_chunk_ids` не заполнены.
Поэтому параметр сохраняется как метаданные запуска, но не выбирает коллекцию
Qdrant и практически не влияет на метрики.

### `search_mode`

Режим поиска:

- `hybrid` — dense и sparse prefetch с последующим ColBERT rerank;
- `dense` — семантический ANN-поиск по dense-векторам BGE-M3;
- `sparse` — поиск по sparse-векторам BGE-M3.

Как основной baseline выбран `hybrid`.

### `top_k`

Количество выданных результатов поиска после ранжирования.

Параметр влияет на состав `retrieved`, итоговый контекст и метрики. Для расчёта
`de_recall_at_10` значение должно быть не меньше `10`.

### `prefetch_k`

Размер предварительной выборки кандидатов для режима `hybrid`.

В текущей реализации:

- dense prefetch получает `prefetch_k / 2` кандидатов;
- sparse prefetch получает `prefetch_k` кандидатов;
- после объединения ColBERT выбирает итоговые `top_k`.

Параметр не используется в режимах `dense` и `sparse`. Увеличение обычно повышает recall, но увеличивает время поиска.

### `use_rewriter`

Разрешает перефразирование исходного вопроса перед поиском.

перефразирование выполняется только когда:

```text
use_rewriter = true
rewrite_system_prompt не пустой
```

### `rewrite_system_prompt`

Системный prompt для модели, перефразирующей поисковый запрос.


Для вызова используется модель `LLMConfig.REWRITER_MODEL` на `LLMConfig.REWRITER_BASE_URL`.

### `expand_refs`

Разрешает расширение результатов по ссылкам и связанным частям таблиц.

При включении retriever:

- находит чанки, на которые ссылаются первые результаты поиска;
- добавляет связанные части найденных таблиц;
- учитывает расширенные чанки при расчёте `ee_recall`.

Расширение применяется только если `ref_depth` больше `0`.

### `ref_depth`

Максимальная глубина переходов по ссылкам.

- `0` — расширение отключено;
- `1` — только непосредственные ссылки;
- `2` — ссылки из найденных по ссылкам чанков.

Текущий защитный лимит в retriever равен `2`. Значения выше `2` фактически
будут ограничены до `2`.

### `compose_system_prompt`

Системный prompt для генерации итогового ответа.

Ответ генерируется только при непустом значении. Если значение пустое:

- `pipeline_result.answer` будет `null`;
- generation-метрики посчитать нельзя;
- в отчёте generation-метрики будут `n/a`.

### `judge_model`

Имя LLM, оценивающей сгенерированный ответ. На наданный момент везде применяется одна легковесная модель

Judge оценивает:

- `faithfulness_score` — подтверждённость ответа найденным контекстом;
- `answer_relevance_score` — релевантность ответа исходному вопросу.

Значение `null` отключает generation-метрики. Непустой `judge_model` имеет
смысл только при непустом `compose_system_prompt`, иначе ответ отсутствует.
